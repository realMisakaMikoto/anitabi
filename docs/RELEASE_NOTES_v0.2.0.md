# 巡礼手帖 v0.2.0

这是一次新增首次启动导览、多作品联合巡礼并补强路线可靠性的功能版。

## 新功能

- 全新安装或尚未完成设置的用户会先进入三步导览：了解用途、一次请求定位与通知权限、打开 HeiGIT 申请并填写个人 ORS Key；三项未就绪前不会进入地图。
- 权限被拒绝时会准确显示缺少定位、通知或两者，并提供重试与系统设置入口；Android 8–12 不会错误要求不存在的运行时通知权限。
- ORS Key 输入默认隐藏、可手动显示，经 Android Keystore 加密后只保存在本机；已有本机 Key 的升级用户无需重复填写。路线规划页也新增“如何获取 ORS Key”入口。
- Bangumi 搜索结果现在支持多选动画；已选作品会保留在可横向滚动的标签栏中，可跨多次搜索继续添加或单独移除。
- “查看地图”会把所有已选动画的巡礼点合并到同一张 MapLibre 地图，仍可单点、列表或按当前地图范围自行勾选。
- 合并点位使用“Bangumi 作品 ID + Anitabi 点 ID”的稳定命名空间，避免不同作品的点位 ID 冲突；多作品列表、规划和导航中的点名会带作品标题。
- 多作品选点可以直接生成一条联合路线，原有道路 12 点、公交 8 点限制继续生效。
- 新增与应用配色一致的自适应、圆形和单色启动图标。

## 路线与错误修复

- ORS Matrix 现在明确发送 `distance`、`duration` 和米制单位；Directions 明确发送中文转向指令选项。此前这些默认字段会被序列化器省略。
- 公交抵达内部换乘点时，如果下一班车已超过出发时间和两分钟宽限，应用会按当前时间自动重算剩余行程；到达巡礼点和取消班次的原有自动重算继续保留。
- 拒绝通知权限时不再仅检查定位权限；应用会分别提示缺少定位、通知或两者，并阻止启动不完整的后台导航。
- 404、429、5xx 和其他 HTTP 错误不再把上游响应正文放进异常消息；搜索、ORS 和 Transitous 都显示本地化、不会泄露响应内容的提示。

## 构建与兼容

- 版本号为 `versionCode=6` / `versionName=0.2.0`，最低 Android 8/API 26，目标 Android 17/API 37。
- 更新到 Gradle 9.6.1、AndroidX Core 1.19.0 和 kotlinx.coroutines 1.11.0；release 开启 R8 与资源压缩。
- ORS Key 仍只由每位用户自行申请并经 Android Keystore 加密保存在本机；APK、仓库和发布说明不包含共享 Key。
- Transitous 请求仍为用户/到站事件触发、逐段串行、无轮询、无并发抓取和无自动网络重试。

- 本地 49 个 JVM 单元测试全部通过，0 failure/error/skipped；Android SDK 37 debug、androidTest APK 编译和 Lint 通过，Lint 报告为 0 项。
- 发布工作流只有在 release 测试、Lint、R8、APK 内容审计和固定签名全部通过后才会创建 Release；签名证书 SHA-256 继续为 `9679c83769368c7150f629d9cba3c0e5d633fa7f1043ce251fdba6c7c64fb00a`。
- Xiaomi 15T Pro（Android 16/API 36）已对导览加入前的同版本签名候选完成原位升级和多作品真机检查：合并显示 3 部作品、178 个可用地点，并保持单点选择和规划入口。最终导览首屏由 Android 8/17 自动冷启动检查覆盖，真机需在设备重新连接后复验。
- 用户已确认此前真机连续导航的中文 TTS 可以听到。

## 已知边界

- 手机上仍有另一个假定位应用获得系统 mock-location 权限，因此本轮不把定位管线测试冒充为真实 GNSS 实走。
- 本地验收时手机未连接 ADB，不能把首次启动导览冒充为已完成真机复验；发布后的首屏截图和真机复验会分别记录。
- 8–12 点真实步行/驾车、长时间小米省电限制和真实错过班次仍属于现场测试；自动重算策略已由确定性单元测试覆盖。
- 已发送到聊天中的旧 ORS Key 应由所有者撤销并重新生成；本版本没有写入或分发该值。
